Guía rápida · Herramienta

Programa seguro desde el primer commit

Lo esencial para que tu código llegue a producción sin las vulnerabilidades que siempre aparecen en una auditoría. Arma tu checklist, genera la configuración de headers, CSP y cookies, analiza la respuesta de tu servidor y revisa tu código. Todo se procesa en tu navegador; nada se envía a ningún servidor.

  • OWASP Top 10:2025
  • OWASP ASVS 5.0
  • OWASP API Top 10
  • OWASP LLM Top 10 2025
  • CWE Top 25 (2025)
  • Mozilla TLS

Las 12 reglas de oro

  1. No confíes en nada del cliente.Formularios, query, headers, cookies, JSON, archivos y respuestas de IA se validan en el servidor.
  2. Nunca concatenes entrada.Ni en SQL, ni en comandos, plantillas o eval. Parametriza.
  3. Escapa lo que pintas.Autoescape y textContent; nunca innerHTML con datos.
  4. Permisos en cada endpoint y objeto.Ocultar un botón no es seguridad.
  5. Cero secretos en el código.Ni contraseñas, ni API keys, ni tokens, ni llaves.
  6. Contraseñas con Argon2id o bcrypt.Nunca MD5, SHA-1 ni SHA-256.
  7. Solo HTTPS (TLS 1.2/1.3).Y nunca verify=False.
  8. Headers de seguridad y CSP.En todas las respuestas.
  9. Cookies con flags.HttpOnly, Secure, SameSite y prefijo __Host-.
  10. Librerías actualizadas y fijadas.Lockfile, auditoría y Dependabot/Renovate.
  11. Errores genéricos al usuario.El detalle técnico, solo en el log del servidor.
  12. IA con cuidado.No pegues secretos ni datos de clientes; revisa todo lo que sugiera.

Entradas

Inputs: cómo debe ir cada entrada

Regla: valida en el servidor con un esquema estricto: tipo, longitud, rango y formato; acepta solo lo permitido (allow-list) y rechaza campos extra.

Tipo de datoCómo validarlo
Texto libreLongitud mínima y máxima, sin caracteres de control; se escapa al mostrarlo.
Email, teléfono, documentoFormato con regex o tipo específico (EmailStr, z.string().email()).
IDsTipo estricto (int > 0, UUID) y verificación de que el recurso pertenece al usuario.
Números o montosRango (min/max); montos en Decimal o centavos enteros, nunca float.
Valores de una listaEnumeración cerrada (Literal[...], z.enum([...])).
URLsSolo https:// y dominios permitidos si el servidor las va a llamar (evita SSRF).
ArchivosTamaño máximo, tipo real por magic bytes, nombre generado por el servidor, fuera del webroot.
JSON completoRechaza campos no declarados (extra="forbid" / .strict()).
Python · Pydantic
from typing import Literal
from pydantic import BaseModel, Field, EmailStr

class CrearUsuario(BaseModel):
    model_config = {"extra": "forbid"}   # rechaza "role": "admin"
    nombre: str = Field(min_length=2, max_length=80)
    email: EmailStr
    edad: int = Field(ge=18, le=120)
    plan: Literal["basico", "pro"]
TypeScript · Zod
const CrearUsuario = z.object({
  nombre: z.string().min(2).max(80),
  email: z.string().email(),
  edad: z.number().int().min(18).max(120),
  plan: z.enum(["basico", "pro"]),
}).strict();

const data = CrearUsuario.parse(req.body);

Headers de seguridad: cuáles y para qué sirve cada uno

HeaderValor recomendadoPara qué sirve
Strict-Transport-Securitymax-age=63072000; includeSubDomainsObliga al navegador a usar siempre HTTPS; nadie en la red puede forzar HTTP.
Content-Security-PolicyVer sección CSPDefine qué scripts, estilos e iframes puede cargar la página; barrera principal contra XSS.
X-Content-Type-OptionsnosniffImpide que el navegador "adivine" el tipo y ejecute un upload como script.
X-Frame-OptionsDENYImpide cargar tu página en un iframe ajeno (clickjacking).
Referrer-Policystrict-origin-when-cross-originNo filtra la URL completa (tokens, IDs) a otros sitios.
Permissions-Policycamera=(), microphone=(), geolocation=()Apaga APIs del navegador que no usas para que un script inyectado no pueda usarlas.
Cross-Origin-Opener-Policysame-origin (o same-origin-allow-popups si usas OAuth/pagos en popup)Aísla tu ventana de las abiertas por otros sitios.
Cache-Controlno-store en respuestas privadasEvita datos sensibles en caché del navegador o proxies.
Server con versión, X-Powered-ByEliminarlosNo regales la tecnología y versión exactas para buscar exploits.

Herramienta

CSP (Content Security Policy)

Qué es: la lista de fuentes desde las que tu página puede cargar y ejecutar contenido. Si un atacante logra inyectar un <script>, el navegador no lo ejecuta porque no está autorizado.

Sin 'unsafe-inline' ni 'unsafe-eval'

Anulan la protección contra XSS.

Sin comodines ni listas de dominios

Usa nonce o hash + 'strict-dynamic'; las allow-lists se evaden con JSONP y redirecciones.

Despliega en Report-Only primero

Ves qué se rompería antes de bloquear; luego la haces obligatoria.

Cookies: flags obligatorias

FlagPara qué sirve
HttpOnlyJavaScript no puede leer la cookie: un XSS no roba la sesión.
SecureSolo viaja por HTTPS.
SameSite=Strict / LaxNo se envía en peticiones desde otros sitios (mitiga CSRF).
Prefijo __Host-Obliga a Secure y Path=/, prohíbe Domain: un subdominio no puede sobrescribirla.
Max-Age cortoLimita el tiempo útil de una sesión robada.

Además: regenera el ID de sesión al hacer login, invalídalo en el servidor al hacer logout, usa token anti-CSRF en formularios y nunca cambies estado con GET.

Decisiones

¿Hardcodear? ¿Ofuscar?

Regla absoluta: NO se hardcodean contraseñas, API keys, tokens, llaves privadas ni cadenas de conexión. Tampoco en tests, Dockerfiles, docker-compose.yml, .env versionado ni notebooks.

Python · NO
API_KEY = "sk_live_51H..."
JWT_SECRET = os.getenv("JWT_SECRET", "changeme")
Python · SÍ
from pydantic_settings import BaseSettings
from pydantic import SecretStr

class Settings(BaseSettings):
    api_key: SecretStr      # sin default: si falta, no arranca
    jwt_secret: SecretStr

settings = Settings()

Dónde van los secretos

Vault, AWS Secrets Manager o Azure Key Vault; variables de entorno inyectadas en runtime; en CI/CD, OIDC en lugar de llaves fijas.

Antes del commit

gitleaks como pre-commit hook y .gitignore con .env*, *.pem, *.key.

Si se filtró uno

Primero revoca y rota; después limpia el historial. Borrarlo en otro commit no basta.

Variables públicas

NEXT_PUBLIC_, VITE_, REACT_APP_ terminan en el bundle: son públicas.

¿Ofuscar? Todo lo que se envía al cliente se puede leer

¿Qué hago?Respuesta
Minificar el JS en producciónSÍTerser/esbuild: reduce tamaño, elimina comentarios y logs.
Publicar source maps (.map)NOGenéralos en modo hidden y súbelos solo a Sentry.
Ofuscar todo el frontendNOSolo módulos de alto valor (anti-bot), midiendo el rendimiento.
API keys privadas en el frontend o la appNUNCAEl frontend llama a tu backend; el backend al tercero.
Precios, descuentos o permisos en el clienteNOEl cliente envía la intención; el servidor calcula y valida.
App Android releaseSÍR8/minify, debuggable=false, allowBackup=false, tokens en Keystore.
App iOS releaseSÍTokens en Keychain y símbolos eliminados.
